### Metric: F2
- metric ทางการ: F2 score
- **TODO:** ใส่ link หน้า Evaluation ของ competition เป็นที่มา
- F2 เป็นคะแนนแบบ label-based จึงต้องส่ง label ไม่ใช่ probability
- F-beta คือ weighted harmonic mean ของ P กับ R โดย harmonic mean ถูกดึงเข้าหาค่าที่ต่ำกว่า จึงโกงด้วยการดันค่าใดค่าหนึ่งให้สูงสุดไม่ได้
  ตัวอย่าง: P = 1.0, R = 0.02 → arithmetic mean = 0.51 แต่ F1 ≈ 0.039
- derive เองจากนิยาม:
  - F1 = 2TP / (2TP + FP + FN) = TP / (TP + ½(FN + FP)) → FN กับ FP มีน้ำหนักเท่ากัน คนละครึ่ง
  - Fβ = TP / (TP + (β²·FN + FP) / (1 + β²)) → β = 2: FN ได้น้ำหนัก 4/5 และ FP ได้ 1/5 แปลว่า **FN แพงกว่า FP 4 เท่า**
- β มาจากต้นทุนในโลกจริงของ FN เทียบกับ FP ไม่ได้มาจากความ balance ของข้อมูล
  (เคยเข้าใจผิดว่าข้อมูล balanced ต้องใช้ F1 ภายหลังหักล้างได้ด้วยกรณีมะเร็ง 50/50 ที่ควรใช้ β > 1 และกรณี spam 1% ที่ควรใช้ β < 1)

### FN / FP ในโลกจริง และ use case
- FN = คนที่มีประวัติโรคหัวใจหรือหัวใจวาย แต่โมเดลบอกว่าไม่มี
- FP = คนที่ไม่มีประวัติ แต่โมเดลบอกว่ามี
- use case: ใช้คัดกรองว่า "เสี่ยง / ไม่เสี่ยง" ก่อนส่งต่อให้แพทย์ โมเดลไม่ได้เป็นผู้วินิจฉัย
  ถ้าคนไข้มาที่ช่องซักประวัติแล้วโมเดลบอกว่าไม่เป็นอะไร ทั้งที่จริงเสี่ยง จะเสียหายมาก ส่วน FP มีต้นทุนแค่เวลาแพทย์ จึงเห็นด้วยกับ β = 2
- คำถามเปิด: ทำไมต้อง 4 เท่า ไม่ใช่ 2 หรือ 10? (ในงานจริงขึ้นกับข้อจำกัดในการทำงาน เช่น จำนวนแพทย์)

### Finding 1: `Told High Cholesterol` หายเฉพาะคนที่ไม่ได้ตรวจคอเลสเตอรอล

_ผู้ใช้เขียนช่องคำถาม คำทำนาย และการตัดสินใจ ส่วนช่องที่เหลือ Claude เรียบเรียงจากคำตอบของผู้ใช้ในแชต ตามที่ผู้ใช้ขอ (นับเป็น summon S4) · Claude รันตรวจตัวเลขทุกตัวแล้ว 2026-11-26_

- **คำถาม:** TC หายไป 14.4% (n = 32,186) เราควรลบไปเลยไหม ถ้าไม่ลบ เพราะอะไร
- **คำทำนาย (ก่อนรัน):**
  - เช็กครั้งแรก (กลุ่มที่ TC หาย, cell `highCholIsna`): **ไม่ได้เขียนคำทำนายไว้ก่อนรัน**
  - เช็กอีกทิศ (กลุ่มที่ TC มีค่า, cell `train_not_null`): "ทำนายว่า Cholesterol Checked ไม่ได้มีค่าเท่ากับ Told High Cholesterol แต่ถ้ามันมีค่าเท่ากันหนึ่งต่อหนึ่ง ก็อาจจะปล่อยให้ Told High Cholesterol เป็นค่าว่างต่อไปได้เลย เพราะว่างเพราะยังไม่ได้ตรวจ" → ผล: ไม่ได้ตรงกันหนึ่งต่อหนึ่ง **ตรงตามที่ทำนาย**
- **หลักฐาน:**
  - กลุ่มที่ TC หาย (n = 32,186): Checked = No **100%** (cell `highCholIsna`)
  - กลุ่มที่ TC มีค่า (n = 190,898): Checked = No **3.7%** หรือ 7,114 คน (cell `train_not_null`)
    - แยกย่อย: ในคนที่ TC = No มี Checked = No 5.0% · ในคนที่ TC = Yes มี Checked = No 1.9%
  - สรุปได้แค่ทิศเดียว: ถ้า TC หาย แปลว่าไม่ได้ตรวจ แต่คนที่ไม่ได้ตรวจไม่ได้มี TC หายทุกคน
- **การตัดสินใจ:**
  - แทนค่าที่หายด้วย class ใหม่ `Unknown` ตอน encode เพราะถ้าเติม No เราไม่สามารถยืนยันได้ว่าคนที่ไม่ได้ตรวจทุกคนไม่ได้มีคอเลสเตอรอลสูง (No ของคนที่ตรวจแล้ว กับของคนที่ไม่ได้ตรวจ มีความหมายต่างกัน)
    ใช้ชื่อ `Unknown` แทน "Not checked" เพราะ skip logic ไม่ได้ตรงทุกแถว ชื่อจึงไม่ควรอ้างกลไกเกินหลักฐาน
  - 7,114 แถวที่ Checked = No แต่ TC มีค่า: ปล่อยไว้ตามเดิม เพราะไม่ว่าคำอธิบายจะเป็นแบบไหน การตัดสินใจก็ไม่เปลี่ยน (value of information)
- **เปลี่ยนแผนจากเดิมอย่างไร:** แผนเดิมคือ `dropna` (ลบทุกแถวที่ TC หาย) → เปลี่ยนเป็นเก็บแถวไว้ แล้วใส่ `Unknown`
- **open questions:**
  - 7,114 คนนั้นคือใคร (ยังไม่เร่ง เพราะคำตอบไม่เปลี่ยนการตัดสินใจ) hypothesis ที่มีตอนนี้:
    (ก) เคยตรวจก่อนช่วงเวลาที่คอลัมน์ Checked นับ (ข) ตอบผิดหรือจำผิด
    (ค) "รู้ตัวอยู่แล้วเลยไม่ไปตรวจ": hypothesis นี้ทำนายว่าคนที่ TC = Yes จะไม่ตรวจมากกว่า แต่ข้อมูลได้ 1.9% เทียบกับ 5.0% ผู้ใช้ยังไม่ได้สรุปว่า hypothesis นี้ยังรอดหรือไม่
    ถ้าจะหาคำตอบ ต้องไปดูนิยามคอลัมน์จากแหล่งข้อมูลต้นทาง
  - `test.csv` มี TC หายในรูปแบบเดียวกันไหม และถ้าใช้แผนเดิม (ลบแถวใน train) แถวที่หายใน test จะจัดการอย่างไร ในเมื่อต้องทำนายให้ครบทุก ID
  - mode ของ TC คือค่าไหน ถ้าเป็น No การเติมด้วย mode ก็คือการเติม No
