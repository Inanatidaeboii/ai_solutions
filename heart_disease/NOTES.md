### Metric: F2
- metric ทางการ: F2 score
- **TODO:** ใส่ link หน้า Evaluation ของ competition เป็นที่มา
- F2 เป็นคะแนนแบบ label-based จึงต้องส่ง label ไม่ใช่ probability
- F-beta คือ weighted harmonic mean ของ P กับ R โดย harmonic mean ถูกดึงเข้าหาค่าที่ต่ำกว่า จึงโกงด้วยการดันค่าใดค่าหนึ่งให้สูงสุดไม่ได้
  ตัวอย่าง: P = 1.0, R = 0.02 → arithmetic mean = 0.51 แต่ F1 ≈ 0.039
- derive เองจากนิยาม:
  - F1 = 2TP / (2TP + FP + FN) = TP / (TP + ½(FN + FP)) → FN กับ FP มีน้ำหนักเท่ากัน คนละครึ่ง
  - Fβ = TP / (TP + (β²·FN + FP) / (1 + β²)) → β = 2: FN ได้น้ำหนัก 4/5 และ FP ได้ 1/5 แปลว่า **FN แพงกว่า FP 4 เท่า**
- β มาจากต้นทุนในโลกจริงของ FN เทียบกับ FP ไม่ได้มาจากความ balance ของข้อมูล
  (เคยเข้าใจผิดว่าข้อมูล balanced ต้องใช้ F1 ภายหลังหักล้างได้ด้วยกรณีมะเร็ง 50/50 ที่ควรใช้ β > 1 และกรณี spam 1% ที่ควรใช้ β < 1)

### FN / FP ในโลกจริง และ use case
- FN = คนที่มีประวัติโรคหัวใจหรือหัวใจวาย แต่โมเดลบอกว่าไม่มี
- FP = คนที่ไม่มีประวัติ แต่โมเดลบอกว่ามี
- use case: ใช้คัดกรองว่า "เสี่ยง / ไม่เสี่ยง" ก่อนส่งต่อให้แพทย์ โมเดลไม่ได้เป็นผู้วินิจฉัย
  ถ้าคนไข้มาที่ช่องซักประวัติแล้วโมเดลบอกว่าไม่เป็นอะไร ทั้งที่จริงเสี่ยง จะเสียหายมาก ส่วน FP มีต้นทุนแค่เวลาแพทย์ จึงเห็นด้วยกับ β = 2
- คำถามเปิด: ทำไมต้อง 4 เท่า ไม่ใช่ 2 หรือ 10? (ในงานจริงขึ้นกับข้อจำกัดในการทำงาน เช่น จำนวนแพทย์)
